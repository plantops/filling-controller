# SP01 Specification

Canonical v0.1 behavior for one spout.

## Operation modes

### MANUAL

Machine is stationary. `DI04 process.initiative` is used as the physical ON/OFF fill switch.

```text
OFF -> idle, all fill outputs off
ON  -> acquire bag -> tare -> coarse -> fine -> cutoff -> settle -> COMPLETE
```

Rules:

- `machine.motor_running` is not required;
- `downstream.conveyor_ready` is not required;
- fill position and discharge reference sensors are ignored;
- `bag.push` is never energized;
- after one bag reaches COMPLETE, controller stays complete while switch remains ON;
- switch OFF returns to idle and immediately removes filling outputs;
- changing MANUAL/AUTO during an active cycle faults safe.

### AUTO

Machine rotates and SP01 repeats the full cycle automatically:

```text
WAIT_PERMISSIVE
-> WAIT_FILL_POSITION
-> BAG_ACQUIRE
-> BAG_VERIFY
-> TARE_READY
-> COARSE_FILL
-> FINE_FILL
-> CUTOFF
-> SETTLE
-> WAIT_DISCHARGE
-> PUSH
-> COMPLETE
-> next cycle
```

## Speed-adaptive discharge

Fixed time delay is not used for discharge position.

SP01 measures the travel time from reference A to reference B, then uses the same normalized count unit for the post-B countdown.

```text
ref A -> count up / measure A-B interval
ref B -> start normalized countdown
countdown = measured A-B interval * configured_count_ratio
push     -> when countdown expires
```

Firmware normalizes A->B to 1000 counts. `discharge_lead_counts` trims the configured countdown in the same normalized unit, so the command tracks rotor speed instead of a fixed millisecond delay.

Exact sensor angles and lead setting are commissioning values.

## Timing context

At 2,000 bags/h with 8 spouts:

```text
bag interval       1.8 s
SP01 cycle         14.4 s
```

Actual state timing, cutoff and discharge parameters come from bench and machine measurements.

## Hard rules

- one controller owns one spout;
- one control context commits all physical outputs;
- Wi-Fi/HMI never participates in cutoff or interlocks;
- control never blocks waiting for a Modbus reply;
- stale/invalid weight causes bounded abort;
- MANUAL can never command `bag.push`;
- safety/E-stop remains independent of firmware;
- hardware-specific channel/register details stay in adapters.
