# SP01 Specification

Canonical v0.1 behavior for one spout.

## Sequence

```text
WAIT_PERMISSIVE
-> WAIT_FILL_POSITION
-> BAG_ACQUIRE
-> BAG_VERIFY
-> TARE_READY
-> COARSE_FILL
-> FINE_FILL
-> CUTOFF
-> SETTLE
-> WAIT_PUSH_POSITION
-> PUSH
-> COMPLETE
```

Every state has an entry action, exit condition, timeout and fault path.

## Dosing

```text
OFF     A=0 B=0 C=0
FINE    A=1 B=0 C=1
COARSE  A=1 B=1 C=1
```

## Timing context

At 2,000 bags/h with 8 spouts:

```text
bag interval       1.8 s
SP01 cycle         14.4 s
```

Actual state timing and cutoff parameters come from bench and machine measurements.

## Hard rules

- one controller owns one spout;
- one control context commits all physical outputs;
- Wi-Fi/HMI never participates in cutoff or interlocks;
- control never blocks waiting for a Modbus reply;
- stale/invalid weight causes bounded abort;
- safety/E-stop remains independent of firmware;
- hardware-specific channel/register details stay in adapters.
