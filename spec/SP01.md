# SP01 Specification

Canonical v0.1 behavior for one spout.

## Operation modes

SP01 v0.1 derives operation mode locally from the physical rotor/machine-running signal:

```text
machine.motor_running = OFF -> MANUAL
machine.motor_running = ON  -> AUTO
```

No Wi-Fi/HMI decision participates in this mode selection.

### MANUAL

Machine is stationary. `DI04 process.initiative` is used as the physical ON/OFF fill switch.

```text
OFF -> idle, all fill outputs off
ON  -> acquire bag -> tare -> coarse -> fine -> cutoff -> settle -> COMPLETE
```

Rules:

- `machine.motor_running` is OFF and therefore selects MANUAL;
- `downstream.conveyor_ready` is not required;
- fill position and discharge reference sensors are ignored;
- `bag.push` is never energized;
- after one bag reaches COMPLETE, controller stays complete while switch remains ON;
- switch OFF returns to idle and immediately removes filling outputs;
- if the rotor starts during an active MANUAL cycle, mode change faults safe.

### AUTO

Machine rotates and `machine.motor_running` selects AUTO. SP01 repeats the full cycle automatically:

```text
WAIT_PERMISSIVE
-> WAIT_FILL_POSITION
-> BAG_ACQUIRE
-> BAG_VERIFY
-> TARE_READY
-> COARSE_FILL
-> FINE_FILL
-> CUTOFF
-> SETTLE
-> WAIT_DISCHARGE
-> PUSH
-> COMPLETE
-> next cycle
```

If the rotor stops during an active AUTO cycle, mode change faults safe.

| 6 | `bag.present` | AUTO + MANUAL |
| 7 | `position.discharge_ref_a` | AUTO |
| 8 | `position.discharge_ref_b` | AUTO |

Weight is not a DI. The production signal path is:

```text
load cell -> TLB485 -> isolated RS485 -> ESP32
signal: weight.net + status + timestamp/quality
```

The ESP32 never reads the raw load-cell mV/V signal in production. No v0.1 DI is allocated to continuous weighing data.

## Target recipe strategy

The controller keeps the proven operating compensation model simple. A recipe family may differ only by target weight while the other tuned filling parameters remain unchanged.

```text
50.0 kg
50.1 kg
50.2 kg
50.3 kg
...
```

The operator verifies finished bags on an external check scale and can switch target recipe quickly. Calibration is not changed to compensate production target offset. Automatic AI/learning target correction is outside v0.1.

## Discharge timing

At the nominal SP01 revolution time of 14.4 s, the physical discharge point is fixed once sensor geometry and actuator lead are tuned.

For a single angular reference, the core relationship is:

```text
travel_time = revolution_period * angle_delta / 360
command_delay = travel_time - actuator_lead
```

Therefore discharge is a low-complexity timing problem at fixed speed, and speed variation can be compensated from measured revolution period.

The current v0.1 hardware allocation retains two discharge references A/B. This gives a local speed measurement inside the current revolution:

```text
ref A -> measure A-B interval
ref B -> start speed-normalized countdown
push  -> when countdown expires
```

Firmware normalizes A->B to 1000 counts. `discharge_lead_counts` trims the configured countdown in the same normalized unit.

Two sensors are retained for measurement margin and current-revolution speed information; they are not a fundamental requirement for the discharge concept. A future one-sensor implementation may derive revolution period from consecutive reference pulses if field evidence shows that is sufficient.

Exact sensor angles and lead setting are commissioning values.

## Calibration interlock

Calibration writes are allowed only when all of these are true:

```text
machine.motor_running = OFF
process.initiative     = OFF
controller             = WAIT_PERMISSIVE
all outputs            = OFF
weight                 = fresh + stable + GOOD
TLB calibration writes = explicitly enabled
service token          = valid
```

DI8 is the discharge reference B sensor and is never reused as a service-enable input.

## Timing context

At 2,000 bags/h with 8 spouts:

```text
bag interval       1.8 s
SP01 cycle         14.4 s
```

Actual state timing, cutoff and discharge parameters come from bench and machine measurements.

## Hard rules

- one controller owns one spout;
- one control context commits all physical outputs;
- Wi-Fi/HMI never participates in cutoff, interlocks or AUTO/MANUAL selection;
- TLB485/RS485 is the primary production weight path;
- DI is not used for continuous weight values;
- control never blocks waiting for a Modbus reply;
- stale/invalid weight causes bounded abort;
- MANUAL can never command `bag.push`;
- safety/E-stop remains independent of firmware;
- hardware-specific channel/register details stay in adapters.
