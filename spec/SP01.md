# SP01 Specification

Canonical v0.1 behavior for one spout.

## Mission and lifecycle contract

SP01 is an open replacement controller intended to keep a mechanically valuable rotary packer serviceable after the original controller becomes obsolete or difficult to source.

The lifecycle principle is:

> **DESIGN FOR REPLACEMENT, NOT IMMORTALITY.**

The controller node may be treated as a low-cost replaceable service module provided that failure is contained, outputs fail safe, recovery is quick and critical machine knowledge is recoverable outside the board.

One controller owns exactly one spout. SP01 is not master for the other seven spouts.

Possible machine ambient may reach approximately **70 °C**. The design does not assume the full prototype assembly is automatically qualified at that temperature. Thermal/serviceability behavior is characterized in G2T and field lifetime is treated as an empirical maintenance variable.

## Operation modes

SP01 v0.1 derives operation mode locally from the physical rotor/machine-running signal:

```text
machine.motor_running = OFF -> MANUAL
machine.motor_running = ON  -> AUTO
```

No Wi-Fi/HMI decision participates in this mode selection.

### MANUAL

Machine is stationary. `DI04 process.initiative` is used as the physical ON/OFF fill switch.

```text
OFF -> idle, all fill outputs off
ON  -> acquire bag -> tare -> coarse -> fine -> cutoff -> settle -> COMPLETE
```

Rules:

- `machine.motor_running` is OFF and therefore selects MANUAL;
- `downstream.conveyor_ready` is not required;
- fill position and discharge reference sensors are ignored;
- `bag.push` is never energized;
- after one bag reaches COMPLETE, controller stays complete while switch remains ON;
- switch OFF returns to idle and immediately removes filling outputs;
- if the rotor starts during an active MANUAL cycle, mode change faults safe.

### AUTO

Machine rotates and `machine.motor_running` selects AUTO. SP01 repeats the normal full cycle automatically:

```text
WAIT_PERMISSIVE
-> WAIT_FILL_POSITION
-> BAG_ACQUIRE
-> BAG_VERIFY
-> TARE_READY
-> COARSE_FILL
-> FINE_FILL
-> CUTOFF
-> SETTLE
-> WAIT_DISCHARGE
-> PUSH
-> COMPLETE
-> next cycle
```

This normal path corresponds to a healthy/good bag and ends with the normal push/eject around **355°** after commissioning timing is applied.

If the rotor stops during an active AUTO cycle, mode change faults safe.

## Bag disposition — early reject versus normal discharge

The installed machine has two different eject outcomes for the same rotating spout:

```text
broken bag detected -> push/eject at approximately 210°
healthy/good bag     -> push/eject normally at approximately 355°
```

The 210° value is an **early reject/eject position**, not a broken-bag sensor position.

The broken-bag detection source is a separate input/logic contract and is not yet frozen in the current 8DI model. Do not invent a ninth DI or silently repurpose DI7/DI8.

The process requirement is per-cycle disposition:

```text
GOOD   -> keep bag -> normal eject near 355°
REJECT -> latch reject for this spout/cycle -> early eject near 210°
```

A rejected bag must not subsequently execute the normal 355° push for the same cycle. A good bag must not execute the 210° reject push.

The physical action remains semantically `bag.push`; this fact alone does not create a new `OUT_REJECT` channel. The installed actuator/electrical path must still be verified in G8.

Current executable firmware implements only the normal `WAIT_DISCHARGE -> PUSH` path. The early 210° reject path is therefore a known software gap and must be added/tested before G3 can be considered complete for the installed-machine behavior.

The exact broken-bag detection contract, 210° position reference, normal ~355° position reference, timing windows and actuator lead are commissioning/as-built values. See [`../docs/BROKEN_BAG_REJECT.md`](../docs/BROKEN_BAG_REJECT.md).

## Target recipe strategy

The controller keeps the proven operating compensation model simple. A recipe family may differ only by target weight while the other tuned filling parameters remain unchanged.

```text
50.0 kg
50.1 kg
50.2 kg
50.3 kg
...
```

The operator verifies finished bags on an external check scale and can switch target recipe quickly. Calibration is not changed to compensate production target offset. Automatic AI/learning target correction is outside v0.1.

## Discharge timing

For a single angular reference, the core relationship is:

```text
travel_time = revolution_period * angle_delta / 360
command_delay = travel_time - actuator_lead
```

The **normal healthy-bag discharge** is around **355°**. The current v0.1 hardware allocation retains two discharge references A/B and uses them for the existing normal discharge timing path:

```text
ref A -> measure A-B interval
ref B -> start speed-normalized countdown
push  -> when normal-discharge countdown expires
```

Firmware normalizes A->B to 1000 counts. `discharge_lead_counts` trims the configured countdown in the same normalized unit.

The **broken-bag reject** is a separate earlier angular target around **210°**. Do not assume the current A/B pair can schedule that earlier point in the same revolution. The correct reference/timing method for 210° must be established from machine evidence before implementation.

Two sensors are retained for measurement margin and current-revolution speed information in the normal discharge path; they are not a fundamental requirement for the overall angular-position concept.

Exact sensor angles, reject/normal angular windows and lead settings are commissioning values.

## Calibration interlock

Calibration writes are allowed only when all of these are true:

```text
machine.motor_running = OFF
process.initiative     = OFF
controller             = WAIT_PERMISSIVE
all outputs            = OFF
weight                 = fresh + stable + GOOD
TLB calibration writes = explicitly enabled
service token          = valid
```

DI8 is the discharge reference B sensor and is never reused as a service-enable input.

Replacing only the ESP controller while retaining the same healthy TLB485 must not automatically modify TLB zero/span calibration.

## Serviceability requirements

The production field design shall converge on a replaceable SP01 module with explicit, recoverable configuration.

Required recoverable information includes:

```text
firmware version / commit
spout_id
I/O inversion / channel mapping
TLB serial profile and address
approved target recipes
commissioned timing values
calibration audit metadata
```

Current v0.1 does not yet claim automatic config export/import. That is a pending serviceability capability. Until implemented, the as-built configuration must be recorded outside the board.

A spare controller should be pre-flashed and bench-verified before storage. A field replacement should avoid individual machine-wire re-termination wherever practical.

No hard MTTR number is frozen before a real replacement drill. The design direction is a minutes-scale board swap rather than a rewiring/engineering intervention.

See [`../docs/SERVICEABILITY.md`](../docs/SERVICEABILITY.md).

## Environmental / G2T requirement

Possible ambient near the rotating electronics may reach approximately 70 °C.

G2T shall characterize:

```text
actual machine temperature at controller/TLB locations
controller operation under elevated temperature
representative DO switching
RS485 traffic
Wi-Fi/HMI activity
boot/reset/brownout/fault behavior
safe output state
spare-controller replacement and config recovery
```

Thermal qualification is used to determine safe field behavior, mounting improvements and practical maintenance interval. It is not used to claim an unverified long component lifetime.

The low-cost ESP node may be replaced as a consumable if field lifetime is economically acceptable. The TLB/weighing transmitter remains a separate module and must be relocated or substituted if its own verified environmental capability is inadequate.

## Timing context

At 2,000 bags/h with 8 spouts:

```text
bag interval       1.8 s
SP01 cycle         14.4 s nominal
```

Approximate machine eject positions currently known:

```text
broken-bag reject  ~210°
healthy-bag eject  ~355°
```

Actual state timing, cutoff, angular windows and actuator lead parameters come from bench and machine measurements.

## Hard rules

- one controller owns one spout and is not a master dependency for other spouts;
- one control context commits all physical outputs;
- Wi-Fi/HMI never participates in cutoff, interlocks, bag disposition timing or AUTO/MANUAL selection;
- TLB485/RS485 is the primary production weight path;
- DI is not used for continuous weight values;
- control never blocks waiting for a Modbus reply;
- stale/invalid weight causes bounded abort;
- MANUAL can never command `bag.push`;
- a REJECT disposition, once latched for a cycle, suppresses the normal ~355° push for that cycle;
- a GOOD disposition never commands the ~210° reject push;
- boot/reset/watchdog/fault must leave physical outputs in the defined safe image;
- critical configuration must be recoverable outside the disposable controller;
- controller replacement must not silently alter weighing calibration;
- safety/E-stop remains independent of firmware;
- hardware-specific channel/register details stay in adapters.
